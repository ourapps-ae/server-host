# Source mapping

Reference revision: `19905b75dbea89fbfd424d67fe26c81aaed0e018`. Recipe paths are under `OurPoker/recipe/server/`; realtime-rooms paths are under `components/realtime-rooms/implementation/server/` (read, not changed). `authoring/integration-realtime-rooms.ts` runs the realtime-rooms fixture together with the room-directory Directory class.

- `src/index.ts` lines 9-11 (`allowed`: listed origins, hosted-copy pattern, localhost, `WEB_ORIGINS`) and 23-28 (the default export that adds an accepted origin to `WEB_ORIGINS` before calling the room service) -> `implementation/server/entry.ts` `originAllowed` and `createEntry`: the OurPoker settings object and the `ourapps.app` hosted-copy pattern become the validated settings and an optional `originPatterns` list; loopback stays on by default. Lines 12-22 (the `/update` relay and `/video-rooms` routes) are recipe services and stay with the recipe; lines 1-8 (imports, `Room` and `Directory` re-exports) are the application's module and become the example in `examples/worker.ts`.
- `wrangler.jsonc` lines 1-10 -> `implementation/server/deploy.ts` `renderWrangler`: worker name, entry, compatibility date, dev port, variables, the two object bindings and the SQLite migration (`new_sqlite_classes`) are kept; the invite address variable and the separate `v1`/`v2` migration tags are left behind (one `v1` migration declares every class); `{{applicationId}}` and `{{webAddress}}` became `roomPrefix`-derived name and `allowedOrigins`; an optional paid-plan `limits.cpu_ms` is added after the Cloudflare limits page.
- `package.json` lines 1-23 -> `renderPackage`: scripts and the Wrangler, TypeScript and Workers types versions are kept for the Cloudflare project; the test, simulation and fixture scripts and the Vitest and tsx dependencies stay behind. A Node variant is added.
- `components/realtime-rooms/implementation/server/worker.ts` lines 4-6, 11 (the settings object and the `allowed` origin test used by `createWorker`) and `adapter.ts` line 33 (`Settings`) -> `implementation/server/settings.ts` `roomsSettings`, `parseOrigins`: the host produces exactly the `{applicationId, allowedOrigins, roomPrefix}` object `createWorker` takes.
- `components/realtime-rooms/implementation/server/index.ts` and `components/room-directory/implementation/server/directory.ts` (the Workers APIs the Room and Directory classes use: `ctx.storage.get/put/setAlarm/deleteAlarm/getAlarm`, `blockConcurrencyWhile`, `abort`, `acceptWebSocket` with tags, `getWebSockets`, `getTags`, `setWebSocketAutoResponse`, `getWebSocketAutoResponseTimestamp`, `WebSocketPair`, `WebSocketRequestResponsePair`, `ws.serializeAttachment/deserializeAttachment/send/close/readyState`, `env.X.getByName(...).fetch(...)`, `Response` with status 101 and `webSocket`) -> `implementation/server/node/runtime.ts`, `globals.ts`, `websocket.ts`, `serve.ts`, `loader.ts`, `workers-shim.ts`: `generated-platform`. There is no recipe counterpart; these files implement those calls for one Node process (objects by name, storage on disk with atomic replace, one alarm per object, RFC 6455 server framing, handshake, ping replies and close handling) and were written against the call sites listed here, then run against the real realtime-rooms fixture (see `authoring/integration-realtime-rooms.ts`).
- `implementation/server/region.ts` is new: Cloudflare `jurisdiction()` and `locationHint` placement from the data location page.
- `implementation/server/node/storage-export.ts` follows the style of `components/realtime-rooms/examples/migration.ts` (ndjson with a header and per-record sha256) for the Node adapter's files.
- `implementation/server/host-settings.ts` is new (`generated-platform`): the template aepm renders at install from the five settings, with `fromHostSettings` in `settings.ts` and `createServerHostFromHostSettings` in `host.ts`; the OurPoker server had no counterpart (its settings were the literal object in `src/index.ts` lines 9-11). `tests/render-template.ts` is a pure copy of aepm's `configuration` and `substitute` rules (`aepm/aepm/application.py` lines 63-137) used by the tests; `examples/rendered-host-settings.ts` is a rendered sample.
- `implementation/server/host.ts` and `settings.ts` are new: the typed settings, their checks (secret reference grammar, https origins, region lists) and the single `createServerHost` interface.

Left behind: the OurPoker engine, views, bots, rules and video grants (`src/engine.ts`, `room.ts`, `view.ts`, `bot.ts`, `video.ts`, `services.ts` and the rest), the vitest tests and fixtures, and `INVITE_URL` handling. `package-lock.json` and `node_modules` are not shipped.
